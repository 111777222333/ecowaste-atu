# EcoWaste АТУ — цифровая система учёта пищевых отходов

MVP для Трека 1 хакатона ATU «Smart Food Industries»: облачная веб-система с мобильной версией, которая заменяет бумажные таблицы учёта пищевых отходов АО «АТУ» и сводит их в единую отчётность и аналитику.

**Полный цикл:** форма со смартфона → проверка → единый реестр → аналитика → сводный отчёт (Excel / PDF).

## Быстрый запуск

Нужен только **Node.js ≥ 18**. Внешних зависимостей нет, `npm install` не требуется.

```bash
node server.js            # http://localhost:3000
node server.js --reset    # сбросить базу и заново сгенерировать демо-данные
PORT=8080 node server.js  # другой порт
```

При старте сервер печатает адрес для смартфона в той же Wi-Fi сети (например, `http://192.168.1.20:3000`). Если сеть не пускает, подойдёт туннель: `npx localtunnel --port 3000` или `cloudflared tunnel --url http://localhost:3000`.

Ещё есть офлайн-демо `dist/demo.html` (собирается командой `node build-demo.js`). Это один файл, который открывается в любом браузере без сервера. Данные в нём хранятся в localStorage, поэтому каждый браузер видит свою копию. Для показа «смартфон ↔ ноутбук» с общими данными нужен сервер.

## Публикация через GitHub

**Вариант А: GitHub Pages (статичный сайт, 2 минуты).**
Settings → Pages → Source: *Deploy from a branch* → Branch: `main`, папка `/ (root)` → Save.
Через 1–2 минуты сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.
GitHub Pages не запускает сервер, поэтому сайт работает в демо-режиме: данные хранятся в браузере каждого пользователя.

**Вариант Б: Render из GitHub (настоящий сервер с общими данными, ~5 минут).**
render.com → Sign in with GitHub → New → Blueprint → выберите репозиторий (файл `render.yaml` уже есть) → Apply.
Получится адрес вида `https://ecowaste-atu.onrender.com`: смартфон и ноутбук работают с одной базой.
Бесплатный тариф засыпает после 15 минут без запросов, и первый заход после этого грузится около 30–50 секунд. Откройте сайт за пару минут до защиты.

## Демо-данные

Данные генерируются автоматически при первом запуске (детерминированно, на основе образцов таблиц):

- 5 организаций с видами отходов **точно по образцам** (Кафедра ТПП, Кафедра ТХиПП, ATU INN, Кофейня «Canella», Столовая «Искандер»);
- **4 закрытых месяца + текущий** (≈2 000 взвешиваний), с учётом расписания: кафедры работают по дням лабораторных (вт/чт) и почти не работают летом, столовые — пн–сб;
- отчёты прошлых месяцев приняты, есть история с одним возвратом и повторной отправкой;
- за последний закрытый месяц Кафедра ТХиПП не сдала отчёт, а ATU INN отправил, но проверка ещё не начата. На этих данных видно, как работают «Контроль несдавших» и очередь проверки;
- у Столовой «Искандер» заложен рост нереализованной продукции в прошлом месяце, чтобы аналитика показала отклонение и рекомендацию.

## Сквозной сценарий (раздел 9 ТЗ), около 2 минут

1. **Смартфон** → `iskander@atu.kz`. Откроется форма текущего месяца.
2. Нажмите вид отхода → введите вес → «Сохранить». Повторите 2–3 раза. Итоги за день и месяц пересчитываются сразу.
3. «+ Новый вид» → например «Хлебные корки». Вид сохраняется в справочник организации и сразу появляется в форме.
4. «Отправить на проверку» → статус **Отправлено**.
5. **Ноутбук** → `reviewer@atu.kz` → «Проверка» → откройте отчёт (статус станет **На проверке**). Нажмите «Вернуть на доработку» с комментарием: без комментария система не даст вернуть отчёт.
6. Смартфон: обновите страницу. Видны статус **Возвращено** и комментарий. Исправьте запись («Изменить») и отправьте отчёт снова. На ноутбуке нажмите «Принять». В истории видны все шаги.
7. «Реестр» → фильтр по организации, периоду, виду отходов (и способу утилизации).
8. «Аналитика» → 4 графика, KPI, отклонения, рекомендации; новые данные уже учтены.
9. «Отчёты» → «Квартал» → «Скачать Excel» (3 листа) или «PDF / печать».
10. В разделах «Проверка» и «Отчёты» видно, кто не сдал отчёт за период.

### Сверх ТЗ

- **QR-коды на контейнеры.** Каждой организации и каждому виду отходов генерируется свой QR-код (раздел «QR-коды» в форме или «▦ QR» в админке). Коды можно распечатать наклейками или скачать в PNG. Сотрудник сканирует код камерой телефона, и открывается форма с уже выбранным видом отхода: остаётся ввести вес (2 касания). Если сотрудник не вошёл в систему, после входа его вернёт на ту же форму. В Chrome на Android есть встроенный сканер (кнопка «📷 Сканировать QR», нужен https). QR-генератор — QRCode for JavaScript (Kazuhiko Arase, лицензия MIT), встроен в `public/qr.js`.
- **Рекомендации по сокращению отходов.** Работают по правилам, учитывают структуру отходов организации за 3 месяца и ранжируются по эффекту: органика на полигон → компост или биогаз (с расчётом т CO₂-экв./год); нереализованная продукция → планирование выпуска и фудшеринг; масло → сдача на биотопливо; вторсырьё → раздельный сбор.
- **Потенциал сокращения CO₂** на дашборде: насколько снизятся выбросы, если органику компостировать.
- **Предупреждение об аномальном значении при вводе** (в 3 раза выше среднего по этому виду) ловит опечатки вроде «110» вместо «11,0».
- Кнопки **быстрого входа по ролям** на экране входа экономят время на защите.
- **Офлайн-демо одним файлом** (`dist/demo.html`) работает без сервера и интернета.
- Сброс демо-данных одной кнопкой в админке.

## Архитектура

```
public/            клиент (SPA без фреймворков, без внешних библиотек)
  index.html
  app.js           экраны, маршрутизация, SVG-графики, i18n
  core.js          ВСЯ бизнес-логика и проверка прав (используется сервером)
  xlsx.js          генератор .xlsx без зависимостей
  styles.css
server.js          Node.js HTTP-сервер: REST API POST /api/<метод>, статика, PBKDF2, сессии
data/db.json       хранилище (атомарная запись); создаётся автоматически
build-demo.js      сборка автономного dist/demo.html
docs/              ER-диаграмма, процессы «как есть / как будет», эффекты
```

Хранилище для MVP — JSON-файл, чтобы запуск не требовал ничего, кроме Node.js. Модель данных реляционная (см. `docs/ER.md`), поэтому для пилота её можно перенести в PostgreSQL. Миграция затрагивает только функции `load` и `save` в `server.js`.

## Коэффициенты CO₂

Источник: UK DESNZ/DEFRA, *Greenhouse gas reporting: conversion factors 2024*, раздел Waste disposal.

| Случай | кг CO₂-экв. на 1 кг |
|---|---|
| Органика (food & garden) → полигон / вывоз ТБО | 0,656 |
| Пищевые отходы → компостирование / анаэробное сбраживание | 0,0089 |
| Неорганические отходы → полигон | 0,0089 |
| Переработка | 0,0213 |

Объём (л) пересчитывается в кг по плотности вида отхода (масло 0,92).

## Библиотеки, сервисы и ИИ-инструменты

- Сторонних зависимостей нет: используются только Node.js (http, crypto, fs) и браузерные API. Исключение — встроенный QR-генератор (Kazuhiko Arase, MIT).
- Палитра графиков проверена на различимость при нарушениях цветового зрения.
- ИИ-инструменты: код MVP написан с помощью Claude (Anthropic) как вспомогательного инструмента. Концепция, сценарий и защита — работа команды.
